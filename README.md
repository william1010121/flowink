## Why FlowInk?

- **Keep your Mermaid source.** Uses the official flowchart grammar pinned to Mermaid 12.0.0.
- **Choose your alphabet.** ASCII by default, Unicode when you want box-drawing characters.
- **Keep the graph intact.** Branches, cycles, parallel edges, self-loops, and nested subgraphs.
- **Keep the details.** Chinese text, multiline labels, and plain-text Markdown/HTML content; styles and interactions stay in the parsed data.
- **Use JavaScript.** ESM API, JSDoc-derived TypeScript declarations, and no runtime DOM or external executable requirement.

## Command line (source build)

The published npm **0.1.1** package does not include this CLI. Build this
matching checkout first using [Development](#development), then run from its root:

```sh
node ./dist/cli.js diagram.mmd
cat diagram.mmd | node ./dist/cli.js --charset unicode
node ./dist/cli.js --charset=unicode -- -diagram.mmd
```

Usage: `flowink [--charset ascii|unicode] [--] [FILE|-]`. Omit `FILE` or use
`-` to read standard input. ASCII is the default. Options may appear before or
after the file until `--`; duplicate charset flags and extra operands are errors.
Use `--help` / `-h` or `--version` / `-v` alone.

Input must be valid UTF-8. The CLI preserves a leading BOM and line endings when
passing source to `render(source, { charset })`, and writes exactly that result
plus one LF to stdout. It buffers the complete input and rendered diagram in
memory, with no CLI input-size cap; it is not a streaming renderer. Diagnostics
are escaped and written to stderr without stack traces. There is no network,
configuration, telemetry, or output-file option.

Exit status is 0 for success, help, version, or an intentionally closed stdout
pipe; 2 for invalid arguments; and 1 for input, decoding, rendering, or other
output failures. A closed stdout pipe does not erase an earlier failure. SIGINT
uses Node's native handling (typically status 130 in POSIX shells).

Large inputs can exhaust process memory or require substantial layout time; use
external resource limits for untrusted workloads. Label-control normalization and
escaped diagnostics are not a universal terminal-safety guarantee. Executable/package validation currently
covers Linux on Node.js 22.12 and 24, not Windows.

## Quick start

Requires **Node.js 22.12+**. Install from npm:

```sh
npm install flowink
```

Create `demo.mjs` in your project:

```js
import { parse, render } from 'flowink';

const source = `flowchart LR
  A[Mermaid] --> B[Plain text]
`;

console.log(await render(source));
console.log(await render(source, { charset: 'unicode' }));

const graph = parse(source);
console.log(graph.nodes, graph.edges);
```

```sh
node demo.mjs
```

Browser applications can import `flowink` through their usual bundler.

## API

### `render(source, options?) → Promise<string>`

```js
const ascii = await render(source);
const unicode = await render(source, { charset: 'unicode' });
```

| Option | Values | Default |
| --- | --- | --- |
| `charset` | `'ascii'`, `'unicode'` | `'ascii'` |

Unsafe C0/C1 control characters in labels are replaced with visible `�` after entity decoding; LF and tab normalization are preserved. Labels are plain text, not terminal escape instructions.

Output has no trailing spaces or trailing newline. There is no fixed total width, and labels are not truncated. Dense diagrams may expand to preserve wire spacing and readable label placement.

### `renderGraph(graph, options?) → Promise<string>`

**Source-build API:** Not available in the published npm **0.1.1** package.
Use a matching [source build](#development), not the npm quick-start install.

Render an edited or JSON-deserialized `FlowGraph` directly, without parsing its `source` again. Options and output formatting match `render`.

After building this checkout, run the example from its root (for example, save
it as `demo.mjs` and run `node demo.mjs`):

```js
import { parse, renderGraph } from './dist/index.js';

const graph = parse('flowchart LR\n A[Start] --> B[Done]');
graph.nodes.find(node => node.id === 'A').label = 'Ready';
console.log(await renderGraph(graph, { charset: 'unicode' }));
```

For an unchanged graph with accepted acyclic drawing data, `renderGraph(parse(source), options)` produces the same output as `render(source, options)`. Rendering snapshots drawing data before asynchronous layout and does not mutate the input, so frozen graphs and concurrent calls are supported. Changes made after a call starts affect only later calls.

Graph records must be plain objects from the caller or another realm (or null-prototype objects), with own data properties and ordinary dense arrays. Drawing fields are validated, including directions, identifiers, edge endpoints, arrow/stroke kinds, parents, and group membership. Accessors in drawing data are rejected without invoking them. Invalid graphs reject with `FlowInkError` code `INVALID_GRAPH`; layout failures retain their usual error codes. Graph errors do not fabricate Mermaid source locations.

`source`, styles, classes, and non-drawing metadata are ignored, not executed or reparsed. Text/shape metadata used for drawing is copied and must contain only acyclic data with at most 256 nested levels. Deeper drawing metadata rejects with `INVALID_GRAPH` before layout. Icon/image payloads are not loaded or traversed; only their presence selects a placeholder. This API accepts graph data, not arbitrary JavaScript instances or executable objects; it is not a sandbox for Proxies. Use `parse` followed by edits, or a JSON round-trip of its result, to preserve the graph structure. Cyclic text/shape metadata created by YAML aliases is rejected, even if source rendering accepts it. Ordinary data from same-origin iframes or VM contexts can be passed directly, including mixed-realm arrays and records. Custom class instances, array subclasses, and nonstandard prototype chains remain unsupported.

### `parse(source) → FlowGraph`

Returns an independent, serializable graph, retaining the exact original input.

| Field | Contents |
| --- | --- |
| `source` | Original Mermaid source |
| `direction` | Normalized flow direction |
| `nodes` | IDs, labels, label types, shapes, parents, styles, classes, metadata |
| `edges` | IDs, endpoints, labels, arrows, stroke, length, styles, classes, metadata |
| `subgraphs` | IDs, titles, membership, hierarchy, local directions, metadata |
| `classes` | Named style definitions |
| `metadata` | Frontmatter, directives, accessibility information, and other non-drawing data |

Multiline shape-data declarations (`@{...}`) follow YAML indentation, nested-mapping, and block-scalar rules. Align sibling keys; literal/folded labels retain their scalar content and chomping semantics. Single-line comma-separated shape metadata remains supported. Inconsistent multiline indentation raises `SHAPE_DATA_ERROR` rather than being silently dedented. See [shape-data YAML behavior](docs/shape-yaml-indentation.md).

### Errors

```js
import { FlowInkError, render } from 'flowink';

try {
  console.log(await render(source));
} catch (error) {
  if (error instanceof FlowInkError) {
    console.error(error.code, error.message);
    if (error.line !== undefined) {
      console.error(`Line ${error.line}, column ${error.column}`);
    }
  } else {
    throw error;
  }
}
```

Located syntax errors use one-based lines and UTF-16 code-unit columns in the original source. Unexpected-token errors point to the beginning of the offending token; end-of-input errors retain the parser’s last available location, and lexical failures may have no location. Layout failures are reported explicitly; a successful render must not silently omit an edge.

## Compatibility

**The baseline is Mermaid 12.0.0**, tag `mermaid@12.0.0`, commit [`98a0945`](https://github.com/mermaid-js/mermaid/tree/98a0945418c76238f15df2afaddbba4272656c3b). The official Jison grammar is vendored unchanged and generated into JavaScript during the build. See [grammar provenance](vendor/mermaid/README.md).

```text
Mermaid source → parser + graph model → ELK layout → character grid → text
```

| Feature | Text representation |
| --- | --- |
| Flowchart/graph syntax, chained links, multi-node links, edge IDs | Parsed using the pinned upstream grammar |
| Branches, cycles, parallel edges, self-loops | Orthogonal routes with separate endpoints and collision checks |
| Nested subgraphs and cross-boundary edges | Containers with Mermaid's direction inheritance behavior |
| Common node shapes | Text approximations |
| Other shapes, images, icons | Shape annotations or text placeholders |
| HTML and Markdown labels | Plain text, preserving line breaks and entities |
| Colors, CSS, animation, links, callbacks | Retained as data; callbacks are not executed and images are not fetched |
| Invisible edges | Influence layout without visible strokes |

FlowInk uses its own text layout rather than Mermaid SVG coordinates. Nonjoining crossings use `#` in ASCII and `╳` in Unicode, distinct from corners and junctions. Alignment follows character display widths; fonts and terminals can differ in their Unicode width conventions.

Compatibility covers this version's **flowcharts**, not other Mermaid diagram types or future releases. The package supplies a JavaScript API and a minimal Node.js CLI; an editor UI remains outside its current scope.

## Development

```sh
git clone https://github.com/william1010121/flowink.git
cd flowink
npm ci
npm run build
npm test
npm run test:types
npm run test:package
```

### Verification

The suite covers **435 upstream fixtures**, including complete static inputs and bounded arrow, length, keyword, and character matrices. It also checks graph geometry, labels, Unicode widths, error locations, and repeated/concurrent calls.

- **Parser comparison:** upstream cases use Mermaid's raw parser and FlowDB; preprocessing cases use Mermaid's public API. [Fixture provenance and exclusions](test/fixtures/upstream/README.md).
- **Package installation:** `test:package` checks archive contents and installs the tarball in a temporary directory outside the project.
- **Browser execution:** install Chromium once with `npx playwright install chromium`, then run `npm run test:browser`. It builds the browser bundle, serves it on an ephemeral loopback port, and executes five synthetic diagrams in real headless Chromium. ASCII and Unicode outputs must exactly match Node.js; syntax-error positions and repeatability are also checked. Browser errors, failed requests, incomplete results, mismatches, and timeouts fail the command. `npm run test:browser:runner` verifies these failure guards with deliberately broken pages and then checks the restored page.
- **Manual browser inspection:** `npm run test:browser:build` only generates `.cache/browser-smoke/index.html`; it does not execute a browser. Serve that directory over HTTP to inspect `window.__flowinkSmoke` and the rendered diagrams.
- **CI:** pull requests and pushes to `main` run unit/compatibility tests, build, type checks, and tarball installation on Node 22.12.0 (the minimum), latest 22, 24, and 26. A separate Chromium job runs parity and failure-guard verification. Failed browser jobs retain generated smoke assets for seven days. No release or publishing steps run.

Fixtures are checked in, so tests do not download upstream source on each run. Mermaid itself is a development-only oracle dependency. Rendering is asynchronous but still uses CPU; applications can run large layouts in their own worker.
